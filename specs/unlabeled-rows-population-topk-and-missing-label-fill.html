Purpose

A user porting a food-inspection problem from DSSG triage needs two things. First, triage-pg must treat facilities that were never inspected as "unknown", not as "passed". Second, triage-pg must report precision@k and recall@k with the definition she has been comparing against. Today the first holds by default. The second does not, and nothing tells her so. This plan closes issue #21 and ships the fix as v1.3.0.

Problem

Three gaps, all verified against the code on 2026-10-22:

GapWhereEffect
Top-k ranks only labeled rows. labeled_ranks filters outcome is not null before row_number(). resolve_k turns N_pct into a count of labeled rows. 0015_subset_evaluation.py:91-123, 0002_metric_functions.py:110-113 precision@100 means "top 100 among inspected facilities". DSSG ranked all test rows, cut at k, and then dropped NaN labels (catwalk/evaluation.py:454-457, dssg/master). On DirtyDuck (about 54% labeled) the two numbers differ. The diagnostics already use population ranks (diagnostics/matrixio.py:97), so crosstabs and precision@k disagree on what "top-k" is today.
include_missing_labels_in_train_as does not exist. only src/tests/utils.py:312, in a fixture nothing calls No way to say "count unlabeled train rows as 0 (or 1), keep test rows NULL". A coalesce in the label query cannot express this, because it would also change the test labels and therefore the evaluation.
Unknown keys in label_config / cohort_config are accepted without a message. run.py:353-364 checks only query. The unknown-key warning at run.py:517 covers top-level keys only. A ported DSSG key changes the labels hash (run.py:1257) and does nothing else. include_missing_labels_in_train_as: true gives dropped rows, with no warning.

Solution

D1. Migration 0024 adds triage.population_ranks. It is labeled_ranks with a left join to labels and no outcome is not null filter, so rank_abs ranks every scored row in the population (the subset, when one is given). precision_at_k, recall_at_k, compute_bias_metrics and model_threshold_curve move onto it. k resolves against the population size (ceil kept). Precision becomes TP / labeled rows inside k, and the evaluation row records that denominator in a new num_labeled_above_threshold column. Rank-free metrics (AUC, average precision, Brier, log loss, ECE, regression metrics, C-index) stay on labeled_ranks and are untouched. The same migration recomputes every stored precision@/recall@ row and every bias row in place, then refreshes the leaderboard.

D2. label_config.include_missing_labels_in_train_as (boolean, classification only) becomes a missing_label_fill of 0 or 1 that build_matrix applies to the train matrix's outcome after the label join. The fill enters the train matrix's identity only when set, so no existing hash moves. It is removed from the labels identity, because the labels rows do not change. Retrain reads it back from the train matrix artifact. Test and production matrices never fill.

D3. validate_label_config / validate_cohort_config raise on an unknown key before anything is built, in run_experiment and analyze-config. validate_experiment_config (the dashboard dry run) mirrors them as path-addressed errors.

3. precision_at_k / recall_at_k rewritten over population_ranks

N  = rows in the population          L = rows with outcome is not null      P = outcome > 0
k  = resolve_k(p_parameter, N)       -- ceil kept; was resolve_k(.., L)
m  = labeled rows with rank_abs <= k -- r.num_labeled_above_threshold
tp = positives with rank_abs <= k
r.num_labeled = L;  r.num_positive = P
precision = tp / m      (NULL when m = 0 or k = 0; NULL-but-counts when L = 0)
recall    = tp / P      (unchanged guards: NULL-but-counts when L = 0 or P = 0; 0 when k = 0)
  • [x] Random-ranking baselines. Recall: TP ~ Hypergeom(N, P, k), so value_expected = k/N and value_std = sqrt(k·(P/N)·(1−P/N)·(N−k)/(N−1)) / P, which is today's formula with N for L. Precision: value_expected = P/L, exact conditional on m > 0. value_std comes from a new triage.precision_random_std(N, L, P, k): 
    m ~ Hypergeom(N, L, k) restricted to m > 0;   given m, TP ~ Hypergeom(L, P, m)
E[prec | m] = b = P/L  (constant)  ⇒  Var = E_m[ b(1−b)(L−m) / ((L−1)·m) ]
pmf(m) built in log space by the ratio recurrence
  log w(m+1) = log w(m) + ln((L−m)(k−m)) − ln((m+1)(N−L−k+m+1))
from m_lo = max(1, k−(N−L)) to m_hi = min(k, L), normalised by log-sum-exp.
No lgamma: PostgreSQL has none before 18, and the project supports 11+.
    When L = N (fully labeled), this reduces to today's formula. A test asserts that.
  • [x] Tie bounds are analytic extremes over the boundary tie block, now with three kinds of row (positive, negative, unlabeled). Let s = k − fixed_n, where fixed_n counts every row above the cutoff. 
    precision worst: fill s with tie negatives, then tie unlabeled, then tie positives
precision best : fill s with tie positives, then tie unlabeled, then tie negatives
   value = (fixed_pos + t) / (fixed_lab + negatives_taken + t),  NULL if the denominator is 0
recall  : same TP extremes as today, with tie_n including unlabeled rows
    Fill order is how the extremes are reached: a negative raises the denominator without a TP, and an unlabeled row changes neither.

[x] Phase 5: D1 — bias, curve and diagnostics, then recompute stored rows

owner: sql · depends-on: Phase 4 · files: 0024_population_topk.py, error_tree.py, in_pg_evaluation.py, tests

1. compute_bias_metrics on population ranks

  • [x] Full new body in 0024 (reviewable as one piece). The downgrade restores 0014's body sliced from create or replace function triage.compute_bias_metrics( to the end of UPGRADE_DDL. The signature is unchanged.
  • [x] k = resolve_k(p_parameter, N) over population_ranks, and selected = rank_abs <= k. group_size, num_selected and selection_rate count every row in the group, as Aequitas did with DSSG's full test frame. Rates that compare a prediction with a label use labeled denominators: precision = tp/(tp+fp), fdr = fp/(tp+fp), for = fn/(fn+tn), npv = tn/(fn+tn). tpr/fnr divide by group_pos and fpr by group_neg, as today. Questionables

[asked] Top-k semantics for threshold metrics (D1)

DSSG semantics: rank all test rows in the population, cut at k, then drop unlabeled rows from the metric and record num_labeled_above_threshold. The other options were keeping labeled-only ranking with an ADR, or storing both.

[asked] What to do with include_missing_labels_in_train_as (D2)

Implement DSSG semantics: absent means drop, false means 0, true means 1, train matrix only. The other options were rejecting the key or warning.

[asked] Unknown keys inside label_config / cohort_config (D3)

Fail validation, naming the key and listing the accepted ones.

[asked] Existing evaluations after the upgrade

Migration 0024 recomputes the precision@/recall@ and bias rows in place, so the leaderboard never mixes the two semantics. The other options were an explicit triage evaluate --recompute command, or deleting the rows.

[asked] Release

v1.3.0. SHAP moves to v1.4.0. This is its second renumbering (ADR-0031 note, TODO.org, CLAUDE.md).

[asked] N_pct rounding

Keep ceil and document it. DSSG used int() (floor). k differs by at most one row.

[decided] Add population_ranks instead of changing labeled_ranks

Ten callers use labeled_ranks: AUC, average precision, the probability and regression metrics, calibration, and the 0014/0015 bias and metric bodies. Every rank-free metric needs labeled rows only. Changing labeled_ranks would force outcome is not null into all of them. A second function confines D1 to the four threshold consumers.

[decided] Tie bounds stay analytic extremes

DSSG's "worst"/"best" were sort conventions: na_position='first' for worst and 'last' for best (catwalk/utils.py, dssg/master). They are not true extremes once unlabeled rows sit in the tie block. docs/schema-design.md §3 already chose analytic bounds over DSSG's sampled ones. The two agree whenever the boundary tie block has no unlabeled rows.

[decided] The D2 key is classification-only and boolean-only

DSSG had no problem types, and its key filled a binary label. A 0/1 fill of a continuous outcome is a silent modelling error, and survival has no outcome. A non-boolean value is rejected, as DSSG's else: raise ValueError did. null means absent, as DSSG's None did.

[decided] Identity: the fill is in the train matrix and not in the labels; the experiment hash moves

The labels rows do not change, so the key is stripped from the labels config. Test matrices built on those labels keep their ids. The train matrix carries the fill in its config only when set, so no existing id moves. ADR-0022's problem identity hashes the full label_config, so setting the key starts a new experiment. That is intended, because the training target differs. A config that already carried the key, such as a ported DSSG config, gets a new labels id once and is otherwise unaffected. This goes in the Upgrading note.

[decided] Bias denominators

Group size and selection count every row, as Aequitas did with DSSG's full test frame. Precision, FDR, FOR and NPV divide by labeled rows only, so an unlabeled selected row is not counted as a false positive. Exact Aequitas parity for FOR/NPV with missing labels is not verified, because Aequitas is not installed. This is a non-goal.

[decided] Recomputed bias rows pin their old reference group

bias_metrics stores ref_group_value but not whether it was pinned or chosen as the largest group. Group sizes now include unlabeled rows, so "largest" could change. Passing the stored value as an explicit pin keeps each row's reference stable. New runs use the configured rule.

[decided] The downgrade restores functions but not values

Values recomputed in 0024 stay after a downgrade, because the old values are not kept. Re-running the experiment recomputes them with 0015's functions. The migration docstring says this, so a downgrade is never mistaken for a value rollback.

[decided] Leave sample_config in src/tests/utils.py alone

It is the only place the key appears today, and nothing calls it (checked with grep). After D2 its False would mean "fill 0". It is dead code either way, and deleting it is cleanup outside this issue.

[decided] Validators live in a new problem_config.py

run.py, cli.py and the tests need one definition. The same split already exists for bias (bias.validate_bias_config plus its mirror in validate_experiment_config).

For inspections, "absent" is the right framing. false turns the target into "inspected and failed", which mixes the inspectors' selection into the label. true fits problems where no record means the bad outcome, such as a student who does not re-enroll counting as a dropout.

Why 0007 went the other way, and why that does not hold now

0007 moved the dashboard curve onto labeled-only ranks because the curve mixed a population rank with a labeled total, which pushed pct to 228%. The fault was the mixed denominators, not the population rank. Under D1 both the cut and pct are population-based and precision is labeled-based, so the curve and the leaderboard agree again on a single definition.

Observed, out of scope

  • triage.prediction_ranks partitions by (model_id, as_of_date) but not by split_kind. A model with validation and test predictions on the same date would interleave them.
  • model_threshold_curve joins test labels on m.training_label_timespan and merges every test date into one curve.
  • specs/ is not gitignored in this repo, unlike the session-start assumption. The untracked v1.2.0 plan shows up in git status.
